## B. 기술 충돌

| # | 등급 | 내용 | 제안 | 결정 |
| --- | --- | --- | --- | --- |
| B-1 | 🔴 | **레포 구조.** PRD는 pnpm 워크스페이스(`apps/web`, `packages/*`)인데 현재 레포는 yarn 1 단일 앱이다. | 사용자 확인 대기 | |
| B-2 | 🟠 | **CSP(FR-31) vs SSG(FR-32).** Next 16 문서 기준, 논스 기반 CSP는 동적 렌더링이 필수라 SSG와 함께 쓸 수 없다. | ① Next의 실험 기능 `experimental.sri`(해시 기반, SSG 유지)로 `script-src 'self'` 시도 → ② 안 되면 정적 CSP + `script-src 'unsafe-inline'`. 개인정보 유출을 막는 핵심은 `connect-src`·`img-src`·`form-action` 제한이므로 이쪽은 엄격하게 유지 | |
| B-3 | 🟠 | **Sentry가 FR-30("분석 1종 외 제3자 없음")과 초기 JS 120KB 예산에 걸린다.** Sentry SDK는 단독으로도 예산의 상당 부분이다. | W1에 빈 페이지 번들 크기를 먼저 측정. MVP는 Sentry 제외, 또는 W6에 지연 로드로 추가 | |
| B-4 | 🟠 | **zod가 클라이언트 번들에 들어가면 안 된다.** 룰셋 검증은 빌드 시점, 저장 데이터 마이그레이션(§13.2)은 런타임이다. | 룰셋 = 빌드 시 zod 검증 후 JSON만 번들. 저장 데이터 = 수기 타입 가드 또는 `zod/mini` | |
| B-5 | 🟠 | **룰셋 기준일을 어디서 정하나.** SSG HTML은 빌드 시점 룰셋으로 그려지는데 클라이언트가 `new Date()`로 다시 고르면 하이드레이션 불일치가 나고, 연말 경계에서는 숫자가 달라진다. `cacheComponents: true`라 서버 컴포넌트의 현재 시각 접근도 제약이 있다. | 기준일은 빌드 시 결정해 props로 주입. 룰셋이 바뀌면 재배포(Vercel 예약 배포 또는 수동) | |
| B-6 | 🟡 | §5.2 "쿼리 변형은 정규 URL로 301" ↔ US-012 `/sim?from=salary` 충돌. | `from`도 sessionStorage 핸드오프에만 싣거나, `/sim`의 `from` 파라미터만 예외 처리 | |
| B-7 | 🟡 | `/calc/salary/[amount]`에서 미리 생성한 97개 외의 금액(예: `42500000`) 요청 시 동작이 정의되지 않았다. | `dynamicParams = false`로 404. 서버 런타임 0개 원칙과도 맞다 | |
| B-8 | 🟡 | §17.1에 MDX가 나오지만 스택(§14.1)에는 없다. 법적 고지·계산 방법 콘텐츠 형식이 정해지지 않았다. | MVP는 `copy/ko.ts` + TSX로 통일하고 MDX는 도입하지 않음 | |

## C. 계산·엔진 명세

| # | 등급 | 내용 | 제안 | 결정 |
| --- | --- | --- | --- | --- |
| C-1 | 🟠 | **순자산이 처음부터 음수이면 고갈 나이 = 현재 나이가 된다.** 골든 시나리오 G3(34세, −3,000만원)의 헤드라인이 "34세에 자산이 바닥납니다"가 된다. | 고갈 = "순자산이 0 이상이었다가 처음 0 미만이 되는 나이"로 정의. 음수로 시작하면 "{X}세에 순자산이 플러스로 돌아섭니다" 템플릿 추가(§10.6이 7가지 경우로 늘어남) | |
| C-2 | 🟠 | 음수 금융자산(빚)에도 `nominalReturn` 4%가 붙어 빚 이자를 4%로 계산한다. 실제 신용대출 금리보다 낮다. | MVP는 단순화로 받아들이고 S-07에 명시. 또는 음수일 때만 쓰는 `debtRate` 가정값(기본 6%) 추가 | |
| C-3 | 🟠 | **은퇴 나이 출처가 두 곳이다.** 가정값 패널의 `retirementAge`와 `retirement` 이벤트. 둘 다 UI에 있으면 어느 쪽이 적용 중인지 헷갈린다. | 패널에서는 은퇴 나이를 빼고 이벤트로만 다룸. 또는 패널 값을 바꾸면 이벤트가 생기는 단일 출처 | |
| C-4 | 🟠 | 나이 입력은 64세까지 허용(FR-12)인데 은퇴 기본값은 60. 61–64세 사용자는 첫 해부터 수입 0이 되어 입력한 실수령액이 무시된다. | 은퇴 기본값 = `max(60, age + 1)`, 또는 온보딩에서 은퇴 나이를 함께 묻기 | |
| C-5 | 🟠 | 4대보험 끝전 처리와 장기요양 계산 순서가 원 단위 결과를 바꾼다. 국민연금 기준소득월액 1,000원 미만 절사, 장기요양 = 건보료 × 13.14%와 보수월액 × 0.9448%의 차이 등. | US-005 착수 시 공단 계산기 결과로 역추적해서 확정하고 룰셋 `rounding` 필드에 기록 | |
| C-6 | 🟡 | 간이세액표는 80%·100%·120% 원천징수 선택이 있다. | 100% 고정, "계산 방법"에 명시 | |
| C-7 | 🟡 | `job_change`의 "오늘 가치" 변화액이 이후 임금상승률로 커진다. 물가가 아니라 임금 연동이라는 뜻인데 문서에 명시돼 있지 않다. | 의도대로라면 S-07에 "이직 후 연봉도 임금상승률만큼 오른다"로 설명 | |
| C-8 | 🟡 | 국민연금 가입 연수 `n = retirementAge − pensionJoinAge`는 의무가입 상한(만 60세 미만)을 넘을 수 있다. | `n = min(40, min(retirementAge, 60) − pensionJoinAge)`, 0 미만은 0 | |
| C-9 | 🟡 | 전세 vs 월세의 "손익분기 월세" 공식이 없다. 퇴직금은 평균임금 < 통상임금 보정이 빠져 있다. | 손익분기 = 전세 월 비용 − 월세보증금 × 기회비용 ÷ 12. 통상임금 보정은 MVP에서 빼고 안내 문구로 처리 | |
| C-10 | 🟡 | `/legal/terms`는 사이트맵에만 있고 내용 기준(§17.2)이 없다. | 면책·처리방침과 함께 D-2 법률 검토 범위에 포함 | |
