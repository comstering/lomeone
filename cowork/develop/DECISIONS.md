## 확정 (사용자와 합의, 2026-10-28)

| ID | 결정 | 이유 |
| --- | --- | --- |
| DEV-1 ✅ | **이 레포는 프론트엔드 전용.** 백엔드는 사용자가 별도 구현하고 필요한 것을 API로 제공한다. 프론트는 Vercel 배포, DB·Supabase 등 BaaS는 쓰지 않는다. (PRD D-2 해소: Vercel + 별도 백엔드) | 사용자 지시 |
| DEV-2 ✅ | **프레임워크 = Next.js 16 (App Router)** 유지. 도구 랜딩 SSG, 모임 페이지 CSR, 동적 OG 이미지 | 랜딩 SEO + OG + 모임 페이지를 한 프레임워크로 |
| DEV-3 ✅ | **실시간 갱신 = 폴링 (SWR, 5~10초)**. 내 제출은 낙관적 업데이트로 즉시 반영 | 단순, 카톡 인앱 안정성, 비용 예측. 필요 시 SSE로 교체 가능하게 훅 뒤에 숨긴다 |
| DEV-4 ✅ | **기존 라이프커브 코드 전부 삭제 후 새 pnpm+Turborepo 모노레포.** `cowork/`는 유지. 삭제는 브랜치→PR로만 | 사용자 지시 + `main` 직접 작업 금지 |

| DEV-5 ✅ | **API 계약 = OpenAPI 스펙 단일 출처.** 스펙에서 TS 타입·클라이언트를 자동 생성한다 (백엔드가 springdoc 등으로 생성하거나 프론트가 먼저 작성해 전달) | 불일치 방지 |
| DEV-6 ✅ | **브라우저 → 백엔드 직접 호출(CORS).** BFF 프록시 없음. 총무 키는 요청 헤더로 전송. OG·SSG 등 서버 측 호출만 Next 서버가 백엔드를 부른다. CORS·rate limit은 백엔드 책임 | 지연·비용 최소 |
| DEV-7 ✅ | **MSW 목 + 계약 먼저.** 백엔드 완성 전엔 MSW로 UI를 끝까지 개발하고, 같은 목을 E2E 테스트에도 쓴다. 완성되면 base URL만 교체 | 백엔드 비의존 진행 |

| DEV-8 ✅ | **추천 계산 = 클라이언트 순수 함수(`packages/core`)** (Q-8 옵션 A). 백엔드는 응답 원본만 저장·제공. 백엔드가 같은 로직이 필요해지면 JSON 테스트 벡터를 공유해 일치 검증 | 500ms 반영·필터 UX |
| DEV-9 ✅ | **쓰기 = 낙관적 업데이트(좋아요 패턴) + 멱등 PUT.** 제출·수정·확정은 화면 즉시 반영 후 백그라운드 전송. 실패 시 조용히 롤백하지 않고 "저장 안 됨/재시도" 표시 + 선택 유지 + 자동 재시도. 409(이름 중복)/410(만료)은 롤백+안내. 전송 중엔 폴링 결과 보류. **모임 생성은 낙관적 아님**(서버가 ID 발급). 응답자 토큰은 클라이언트 생성안 권장(OpenAPI 초안에서 확정) | 사용자 작업물 보호 |

| | A. 클라이언트 순수 함수 (`packages/core`) | B. 백엔드가 계산해서 내려줌 |
| --- | --- | --- |
| 내 제출 반영(500ms, AC-04-2) | 응답 원본에 내 것을 합쳐 즉시 재계산 → 서버 왕복 없음 | 낙관적 업데이트 불가, 왕복 후 반영 |
| 칠하는 중 "다른 사람 보기"·필터(1h/2h) | 로컬 재계산으로 즉시 | 필터마다 API 호출 또는 선계산된 변형 필요 |
| 로직 소유 | 프론트가 알고리즘 소유(백엔드는 원본만) | 한 곳, 단 백엔드 구현 부담 증가 |
| 테스트 | Vitest 순수 함수 단위 테스트(AC-04-1 12건) 쉬움 | 백엔드 테스트 + 프론트 표시 테스트로 분산 |
| 응답 데이터량 | 슬롯 원본 전송 필요(31일×28칸×N명, 비트맵이면 작음) | 결과만 → 가볍다 |
| 20명+ / 대형 모임 | 클라이언트 연산 부담(여전히 작음) | 서버가 유리 |
| 카톡 OG(응답 N명/확정) | 응답 수·확정 슬롯은 백엔드가 어차피 제공 | 동일 |
| 위험 | 백엔드·프론트 규칙 불일치 시 서버 알림/OG와 결과가 어긋날 수 있음(예: 서버가 "5/5명 확정 가능" 판단하는 경우) | 규칙이 한 곳이라 불일치 없음 |
